# 책이지 MCP 참조 서버 (chaekiji-mcp) v0.3

부천시립도서관 상호대차 AI 에이전트 「책이지」의 **표준 도구 계층 참조 구현**입니다.
공모 원고의 표준 도구 명세를 실제 MCP(Model Context Protocol) 서버로 구현했으며,
적합성 시험 33건을 통과했습니다(검증기록_20260830.txt).

부천시립도서관 AI 서비스 도입 TF 검토용 참조 구현물입니다.

## 버전 이력

- **v0.3** — 신청 이후가 계약에 들어왔습니다. 실무의 상호대차는 접수로 끝나지 않습니다:
  서가 부재·대출 경합으로 실패하고, 도착 후 미수령으로 자동 취소되며, 이용자가 마음을 바꿉니다.
  이를 위해 `track_request`(생애주기 추적)·`cancel_request`(본인 취소) 도구,
  실패·취소 시 한도 자동 복원, `client_ref` 재시도 멱등성(이중 신청 방지),
  규정 3종(연체·정지 회원, 신착·비도서 제외, 동일 도서 중복)이 추가되었습니다.
  위임(구독)에는 동의 일시·고지문 버전·해지 일시가 기록됩니다 — 감사 대비.
- **v0.2** — 「책이지 패스」(구독형 완전 자동화): `suggest_items`·`manage_mandate`,
  `request_service`의 사전 위임(mandate_id) 실행. 위임 범위(월 권수·무료 경로)를
  벗어나면 스스로 건너뛰고, 해지 즉시 무효화됩니다.
- **v0.1** — 핵심 6종 도구·규정 판정 엔진·설정(YAML) 분리.

## 표준 도구 10종 (핵심 8종 + 확장 2종)

| 도구 | 역할 |
|---|---|
| search_item | 일상어 발화 → ISBN 확정 |
| check_availability | 관내 실시간(모의) → 없으면 전국(정보나루·전일 기준) |
| check_policy | 규정 7종 판정: 수령관 비치·한도 3종·연체 정지·제외 자료·중복 신청 |
| request_service | 신청 실행 — 즉시 확인 또는 사전 위임, 실행 직전 재판정, client_ref 멱등 |
| track_request | [v0.3] 접수→확보→이송→도착(보관기한)→대출/실패/취소 추적, 본인 한정 |
| cancel_request | [v0.3] 본인 취소 — 즉시 한도 복원 |
| find_alternative | 점자·오디오북 대체자료 → 책나래 분기 근거 |
| notify_user | 선호 채널(문자·음성전화) 알림 |
| suggest_items | [확장] 이달의 추천(운영: AI 책큐·정보나루 커넥터) |
| manage_mandate | [확장] 구독 위임장 create/status/revoke — 동의·해지 기록 보존 |

## 무엇이 진짜이고 무엇이 모의인가 (정직 고지)

| 구성요소 | 상태 |
|---|---|
| MCP 서버 (stdio JSON-RPC, 도구 10종) | **진짜** — 표준 클라이언트 연결 가능 |
| 규정 판정 엔진 + 설정(YAML) 분리 | **진짜** — 시험으로 검증 |
| 신청 생애주기·한도 복원·멱등성 | **진짜** — 로직 구현·시험 검증 (상태 전이는 `_sim` 데모 훅으로 재현) |
| 정보나루 커넥터 | demo: 2026. 8. 18. 실측 픽스처 / live: 실제 API 호출 코드 포함(인증키 필요) |
| 알파스 커넥터 | **모의** — 함수 7개가 곧 벤더 연동 명세 (connectors/alpas_stub.py 주석 참조) |
| 회원 데이터 | 가상 인물 모의 데이터 (김○자·박○수) |
| 신착·비도서 제외, 보관기한 값 | **예시 규정** — 기관 확정 규정으로 교체하는 자리 |

`_sim`(상태 전이 훅)은 데모·시험 전용이며 tools/list에 노출되지 않습니다.
운영에서 상태를 바꾸는 주체는 도서관리시스템뿐입니다.

    config/example-city.yaml  가상 도시 — 확산 = 이 파일을 새로 쓰는 일
    connectors/naru.py        정보나루 커넥터 (demo/live 동일 응답 모양)
    connectors/alpas_stub.py  알파스 커넥터 모의 = 벤더 연동 명세 (함수 7개 + 생애주기)
    fixtures/                 실측 소장 · 서지 · 모의 회원
    tests/run_scenarios.py    적합성 시험 킷 (33건)

## 실행

적합성 시험:

    python3 tests/run_scenarios.py

클로드 데스크톱에 연결 (claude_desktop_config.example.json 참조):
설정 파일에 서버 등록 후 재시작 → 대화창에서
"나미야 잡화점 부천에서 빌릴 수 있어? 토큰은 tok_kimsj, 상동 수령"
→ 도구 호출이 실제로 일어나는 것을 확인할 수 있습니다.
이어서 "방금 신청 어떻게 됐어?"(track_request), "취소해줘"(cancel_request)까지
생애주기 전체를 대화로 확인할 수 있습니다.

실계(live) 모드 — 이용자 PC에서:

    NARU_KEY=발급받은키 CHAEKIJI_MODE=live python3 server.py

다른 도시 설정으로:

    CHAEKIJI_CONFIG=config/example-city.yaml python3 server.py

## 확산 절차 (이 저장소가 주장하는 바)

1. 도서관 코드표·규정 숫자를 담은 `config/<도시>.yaml` 작성 — 반나절
2. 도서관리시스템이 알파스면: `alpas_stub.py`의 함수 7개를 벤더 API로 채운 커넥터 재사용
3. 다른 시스템(KOLAS 등)이면: 같은 함수 7개짜리 커넥터 1회 개발 → 전국 공유
4. `tests/run_scenarios.py` 통과 = 책이지 에이전트와 호환 보장

## 참조 구현이 다루지 않는 것 (실전 전환 시 보완 항목)

이 저장소는 표준 도구 계층의 **계약**을 증명합니다. 다음은 예산 확보 후
구축 단계의 몫이며, 의도적으로 범위 밖에 두었습니다:

- 실제 회원 인증 — 도서관 홈페이지/SSO 연동, 토큰 발급·만료·회전 (vault.py는 시연용 고정 토큰)
- 알림 실발송 — 알림톡·SMS 게이트웨이 연계 (send_notice는 큐 적재까지만)
- 저장 계층 — 위임장·신청 이력의 DB 영속화와 암호화 (현재 메모리)
- 성능·가용성 — 도서관리시스템 야간 배치 시간대 부하, 호출 제한, 장애 대비
- 감사 로그 — 개인정보 접근 기록의 기관 감사 시스템 연계
- 운영 규정 확정 — 신착 제외 기간·제외 유형·보관기한 등 예시값의 기관 확정

위 항목들은 **Issues에 개별 과제로 공개**해 두었습니다. 무엇이 남아 있는지를 숨기지
않는 것이 이 저장소의 원칙이며, 도입을 검토하는 기관은 Issues만 보아도 추가로
무엇을 해야 하는지 가늠할 수 있습니다. 의견·제안은 Issue로 남겨 주시면 됩니다.
